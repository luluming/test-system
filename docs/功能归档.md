## 二、数据模型

### 行业（核心隔离单元）

`industries`

| 字段 | 说明 |
|---|---|
| `id` / `code` / `name` / `owner` / `remark` | 基础信息，`code` 全局唯一 |
| `is_template` | 模板源标记，**模板行业禁止删除** |
| `cloned_from_id` | 克隆溯源（自引用 FK），删除父行业时自动置空 |
| `scope` | **归属菜单**：`both`=两个菜单都可见 `nginx`=仅 Nginx 菜单 `yml`=仅 YML 菜单 |

> `scope` 列通过启动时 `_ensure_scope_column()` 做 SQLite `ALTER TABLE` 兼容迁移，旧数据默认 `both`。

### Nginx 族

| 表 | 说明 |
|---|---|
| `nginx_configs` | 配置文件（按行业，含 `config_text`、乐观锁 `version`、编辑租约 `edit_holder`/`edit_heartbeat_at`） |
| `config_blocks` | 泛化块树（`scope` + `parent_id` 表达任意嵌套：server/location/upstream/map/geo/if/comment/raw） |
| `config_options` | 块内 KV / raw 行，顺序即输出顺序 |
| `upstreams` / `upstream_servers` | 上游组与节点（行业级） |
| `domain_mappings` / `forward_ports` / `biz_ports` | 域名映射 / 转发端口 / 业务端口公网开关 |
| `nginx_config_versions` | 版本快照（渲染后全文） |
| `nginx_push_tasks` / `nginx_push_tokens` | 两阶段推送任务 + 一次性 token（只存 SHA-256） |
| `nginx_mirror_pairs` | 镜像监听对（src_listen → dst_listen 跟随） |

### YAML 族

| 表 | 说明 |
|---|---|
| `yaml_configs` | YAML 本体，**原文存 `content_text`（Text 字段，不是文件）**，含 `status`（enabled/disabled/invalid）与乐观锁 `version` |
| `yaml_config_versions` | 版本快照（保存/推送/回滚各存一版完整原文） |
| `yaml_push_tasks` | 推送任务（`raw_text` + `diff_json` + `error_detail`） |
| `yaml_push_tokens` | 推送一次性 token（哈希存储，同 config+purpose 重签即作废旧 token） |

> **重要结论：YAML 配置全部存在 SQLite 表里，不以 `.yml` 文件落盘。**文件系统上只有 `seed_data/deploy_config.yml`（首次种子的只读样例）。

### 其它

`users`（admin/admin123 种子）、`items`（演示 CRUD）。

## 三、已完成功能清单

### 1. 认证与账号 ✅

- 注册 `POST /api/auth/register`
- 图形验证码 `GET /api/auth/captcha`
- 登录 `POST /api/auth/login` → 返回 JWT
- 重置密码 `POST /api/auth/reset-password`（公开路由）
- 修改密码 `POST /api/auth/change-password`
- 当前用户 `GET /api/auth/me`
- 前端：`/login` `/register` `/reset-password`，`ProtectedLayout` 未登录自动跳转；暗色主题适配

### 2. 行业管理 ✅

**双菜单 + 数据隔离（核心需求）**

- 顶部两张模式卡切换：**Nginx 行业管理** / **YML 行业管理**
- 列表按 `scope_filter` 过滤：Nginx 菜单返回 `scope ∈ {both, nginx}`，YML 菜单返回 `scope ∈ {both, yml}`
- 切换模式自动重新拉取列表、统计卡、表格列（Nginx: nginx server / upstream / stream；YML: yml 配置 / 主机 / 集群）
- 行内按钮分别进入对应工作台（`/ops/:id` 或 `/ops/:id/yaml`）
- 统计卡只汇总**当前菜单可见行业**，另一模块数据不会串进来

**新建行业（模板克隆）**

- 弹窗可选模板源；不选则创建空行业（`code` 可手填或由名称派生）
- `clone_scope` 按当前菜单自动决定：YML 菜单 → `yml`，Nginx 菜单 → `nginx`
- 克隆范围：`both` 两套都拷 / `nginx` 只拷配置块树+Upstream+映射+端口 / `yml` 只拷 YAML 及版本快照
- 弹窗标题与按钮会显示当前克隆范围（如「仅 YAML」）

**删除行业（只作用于当前菜单）**

- 两个菜单**完全独立**：删除只处理当前菜单所属模块的数据，另一个菜单的列表与数据绝不会被动到
- 只归属单一模块的行业：清除该模块数据并移除行业记录
- 同时归属两个菜单的模板源行业（`scope=both`）：只清空当前模块数据，归属收敛为另一个模块，行业保留
- 模板源行业：弹窗只显示禁止删除提示，无操作按钮（后端亦返回 400）
- 级联清理按 FK 依赖顺序删除 14 张子表，先断开 `cloned_from_id` 自引用避免 FK 报错

### 3. Nginx 配置工作台 ✅

- 配置文件 CRUD（按行业隔离）
- **块树编辑**：任意层级块增删改、子块查询、同级排序 `PUT /api/config-blocks/reorder`
- 配置项 CRUD 与排序（`/api/config-options`）
- **镜像同步对**：`nginx_mirror_pairs` 管理，可通过 `POST /api/config-blocks/{src}/mirror/{dst}` 同步内容
- **编辑租约**：`edit-heartbeat` / `edit-release` 防多人同时编辑
- **版本快照**：保存即落版本，支持跨版本对比
- **推送两阶段**：`push-tokens` → `push/preview` → `push/{task_id}/apply`，token 一次性、短时过期、哈希入库；任务列表与详情可查
- **一步推送**：`POST /api/nginx-configs/{id}/push`（multipart 上传文件）等价于 preview + apply 合并，一条 curl 完成；认证支持 JWT 或一次性 apply token；文件无变更时返回 `changed=false` 不落任务
- **渲染 / 导出 / 校验 / 重载 / 连通测试**：`render` · `export` · `validate` · `reload` · `test`
- **Upstream 池**：组与节点 CRUD、预览渲染、`validate`
- **域名映射 / 转发端口 / 业务端口**：CRUD，转发端口支持 `/test` 连通性测试
- **拓扑图** `GET /api/topology`、**指令字典** `GET /api/directives`

### 4. YAML 配置工作台 ✅

- 文件列表（含解析统计：是否合法、节点数、版本、更新时间）
- 新建 / 编辑 / 保存 / 删除 YAML 配置
- **结构化树** `GET /api/yaml-configs/{id}/tree`
- **版本管理**：版本列表 + 回滚 `POST /{id}/rollback`
- **推送**：支持上传文件 `push/preview` 按键路径 diff，再 `apply` 落库并生成新版本；一次性 token 机制同 Nginx
- **批量统计** `GET /api/yaml-configs/stats-by-industry`：返回每行业 `yml_count / hosts / clusters / total_nodes`（hosts、clusters 由 PyYAML 解析顶层数组长度）
- **全文搜索**：`Ctrl/Cmd+F` 唤起，浏览/编辑两种模式通用，大小写不敏感、命中计数、Enter/Shift+Enter 上下跳转、命中高亮与滚动定位，Esc 关闭

## 五、关键实现要点与踩坑记录

1. **`env -u LD_LIBRARY_PATH` 必须**：否则 `sqlite3` 符号冲突，后端 import 直接失败。
2. **SQLAlchemy 2.0 批量删除写法**：`db.execute(Table.__table__.delete().where(...))`；Delete 对象没有 `.execute()` 方法。
3. **FK 未设 CASCADE**：删行业必须按依赖顺序手删 14 张子表（ConfigOption → ConfigBlock → version/push/mirror → UpstreamServer → ForwardPort → Upstream → DomainMapping → BizPort → NginxConfig/YamlConfig）。
4. **自引用 FK 陷阱**：`industries.cloned_from_id` 会让「删除被克隆过的父行业」触发 FK violation；删除前必须 `UPDATE industries SET cloned_from_id=NULL WHERE cloned_from_id=<id>`。
5. **seed 幂等但会污染隔离**：启动时只给 `scope ∈ {both, yml}` 的行业补 3 个 YAML 演示文件（`deploy_config.yml` + stage/test 变体），`scope=nginx` 的行业不得出现 YAML 数据。
6. **PyYAML 非严格样例**：`deploy_config.yml` 缩进不齐且存在重复键，需自定义 `UniqueKeyLoader`（继承 `SafeLoader`）同时容忍缩进不齐、拦截重复键。
7. **`compose_yaml` 漏 import**：`api/yaml.py` 顶部必须显式导入 `compose_yaml`，否则 stats 端点运行时报 NameError。
8. **模板行业保护**：后端 400 + 前端弹窗只提示不可删，双保险。
9. **`scope` 列迁移**：SQLite 不支持 `create_all` 给已有表加列，需 `_ensure_scope_column()` 做 `PRAGMA` 检查 + `ALTER TABLE`。

## 七、已知限制 / 可优化项

1. **Nginx 模式统计是 N+1 请求**：Dashboard 逐行业 → 逐配置查树算 server 数，行业多时切换模式会卡；可后端加聚合端点（参考 YAML 的 `stats-by-industry`）。
2. **新建空行业不会立即生成 YAML 演示数据**：seed 仅在启动时运行，空行业需重启后端或手动新建文件才有内容。
3. **YAML 配置存 DB 文本**：无独立文件版本管理、无文件系统目录结构；如需导出落盘需另加导出接口。
4. **无分页**：行业与配置列表均一次性全量返回。
5. **无审计日志**：仅后端 `logger.info` 打点，未建操作流水表。
6. **`items` 为早期演示模块**，与业务无关，可后续清理。
