本地 Nginx 配置推送

一条命令将本地 nginx 配置结构化推入系统 · 端口自动识别 · 差异先预览再确认提交 · 任何变更自动留档版本

1. 背景与目标

当前系统的配置来源与编辑入口都在 Web 端：配置以「行业 → 配置文件 → 监听点（server 块）→ 块树/指令行」的结构化模型保存在数据库中，用户通过块管理页逐块编辑。但系统外的本地服务器（测试机/生产机）上已有一份手工维护的 nginx 配置（站点 conf 文件），它通常才是「事实来源」。把这些配置搬进系统目前只能手工复制粘贴逐块录入，成本高且易遗漏。

产品决策：提供一条推送命令，本地配置文件内容一次性结构化入库，与 Web 编辑无缝衔接；重复推送时按监听点（listen 端口）合并覆盖，而不是整树冲掉。由此形成「本地是生产事实、系统是管理入口」的双向工作流。

期望结果（可观察）：用户在页面复制一条命令（或调用 CLI），仅指定目标配置文件与本地文件路径；命令先返回差异预览（各监听点：替换/新建/无变化/失败，不落库、无副作用），用户确认后二次执行提交；任何失败都不会产生半结构化脏数据；系统内有而文件内没有的监听点始终保留；已入库配置随时可再次修改、可重复推送覆盖。

2. 范围

P0（最小完整旅程）

  • FR-1 获取推送命令：页面生成可复制的 curl 命令模板（仅需指定目标配置文件）；同时提供 CLI 工具两种形态。
  • FR-2 两阶段推送：命令（预览阶段）指定目标与本地文件路径、携带凭证，返回差异预览；确认后（提交阶段）携带预览结果 id 落库提交。
  • FR-3 解析与结构化入库：后端读取配置文本，自动识别全部监听点端口，解析为系统现有块树模型；解析失败全拒并返回行号清单。
  • FR-4 差异对比与提交：预览阶段对每个监听点判定「替换/新建/无变化」（系统内有而文件没有的始终保留）；提交阶段执行替换与新建，生成版本快照，镜像目标联动。
  • FR-5 查看推送结果：预览报告与提交记录（差异清单、失败行号）均可见。
  • FR-6 再次修改：推送入库的配置通过现有块管理页继续编辑。

P1（相关支持）

  • 推送前自动生成一个版本快照（复用「保存=版本」机制），覆盖后可从版本对比恢复。
  • 镜像对联动：被覆盖的监听点若是镜像源，其镜像目标自动跟随同步。

明确排除

  • 从系统向本地服务器反向推送/部署配置（本次只做单向入库）。
  • 本地 nginx 语法校验器、`nginx -t` 集成。
  • 多文件目录批量推送（一次一条命令处理一个文件，可多次推送）。

3. 产品模型

3.1 对象与归属层级

行业→ 配置文件→ 监听点（按 listen 端口标识）→ 块树 + 指令行（options）
  • 监听点标识：同一配置文件内以 listen 端口作为合并键（镜像对场景下监听点是「源端口」身份，如 443）。
  • 推送任务：一次推送 = 一个推送任务，包含预览与提交两阶段；任务持久保留原始文本、差异清单、提交结果与失败行号。
  • 版本快照：所有变更来源自动留档——推送提交成功、系统内修改落库，均自动生成版本记录；版本按时间递增，可任选两版对比。

3.2 推送任务状态机

状态触发可流转到
预览中预览命令已受理，开始读取/解析/对比待确认 / 失败
待确认差异预览已生成，等待用户确认提交提交中（用户二次执行）
提交中确认命令已受理，执行替换/新建落库成功 / 失败
成功提交完成（含自动留档与镜像联动）—（结束态）
失败鉴权失败 / 目标不存在 / 解析错误（全拒）/ 提交时目标已被其他操作改变—（结束态，可修正后重推）
两阶段与副作用边界：预览阶段只读（解析+对比，不写库）；提交阶段才产生写入。提交时若目标配置已与预览时不一致（他人已修改），拒绝提交并提示重新预览。

4. 功能需求

FR-1 获取推送命令 P0

用户与触发：任意已登录用户，在「块管理页」需要把本地文件推入系统时。

处理规则

  • 页面提供「推送配置」入口，弹窗内：选择目标行业与目标配置文件；展示「生成预览命令」按钮。命令无需指定端口——端口在解析时从文件内容自动识别。
  • 生成的 curl 命令内联：API 地址、推送专用凭证、目标配置参数与本地文件路径占位符；支持一键复制。
  • 同屏提供 CLI 工具安装/用法说明：`nginx-push --config <id> --file /path/nginx.conf [--token xxx]`，CLI 与 curl 使用同一套两阶段推送接口。
  • 凭证单独生成（见 FR-2），命令中不暴露登录密码。

结果：命令已复制/CLI 已说明，用户可离开页面到本地执行预览。

命令生成示意（交互演示）

目标：业务中心 / 配置 id 2 
curl -X POST 'http://<api>/api/nginx-push/preview' \
  -H 'Authorization: Bearer <token>' \
  -F 'config_id=2' \
  -F 'file=@/etc/nginx/sites-enabled/af-ftcloud.conf'

端口无需指定：预览命令解析文件后自动识别全部监听点；示例命令随文件路径变化，复制按钮给出反馈。

FR-2 两阶段推送（认证与受理）P0

用户与触发：用户在本地终端执行预览命令；预览确认后执行提交命令。

处理规则

  • 接口鉴权：使用推送专用凭证（Bearer token）。凭证由登录用户在系统内生成、可吊销，与登录会话相互独立。[Assumption, TBD] 凭证生成入口与有效期策略。
  • 预览命令：校验目标配置存在且属于指定行业、文件非空且小于约定上限 [TBD] MB；受理后只读处理（解析+对比），返回差异预览结果，不产生任何库内写入。
  • 提交命令：携带预览结果 id 与相同凭证；校验预览结果仍有效（目标配置自预览后未被其他操作修改），否则拒绝并提示重新预览；提交执行 FR-4 的替换/新建。
  • 任一校验失败：整次拒绝，返回错误与状态码；提交命令拒绝时不写库。

结果与状态：预览 → 待确认；提交 → 成功/失败；命令退出码非零表示失败并打印原因。

FR-3 解析与结构化入库 P0

处理规则

  • 读取文件文本，按系统块树模型解析：识别 http 级块、server 级块（监听点）、location/if/limit_except 子块，以及各级指令行（options，含注释行）。
  • 每监听点以 listen 端口为键登记；缺少 listen 的 server 块视为解析错误。
  • 全拒规则（解析失败）：解析遇到无法映射到块树模型的语法（如部分 include/变量插值/未知块类型），收集错误位置与行号清单，整次推送拒绝入库——不落任何块、不生成版本，返回清单。用户修正文件后可原命令重推。
  • 解析通过后，块树整体落库（复用块/指令的数据结构与层级顺序）。

结果：数据库中出现结构化的目标配置内容；失败时库内无任何新增块。

边界说明：解析覆盖范围与系统现有编辑器一致（http/server/location/if/limit_except + 指令行）。upstream/map/变量等若无法映射，落入失败清单而非被丢弃，避免静默失真。

FR-4 差异对比与提交 P0

对比键 = listen 端口（文件内自动识别），作用域 = 命令指定的目标配置文件

预览阶段（只读，判定每个端口）

  • 替换：文件与系统都有该端口，且结构化内容不同 → 标记替换。
  • 新建：仅文件有该端口 → 标记新建。
  • 无变化：文件与系统都有该端口且内容一致 → 跳过，不进入提交。
  • 保留不删：仅系统有该端口 → 始终保留，不进入差异、不提交删除。
  • 多端口 server：[Assumption] 一个 server 监听多个端口时，以第一个 listen 为对比键，其余端口随该 server 一起替换/新建。

提交阶段（用户确认后执行）

  • 对「替换」端口：该监听点整棵子树（子块+指令行）替换为文件内容。
  • 对「新建」端口：在目标配置下新建监听点。
  • 镜像联动：被替换的监听点是镜像源（如 443↔20551 中的 443）→ 提交完成后自动对其镜像目标执行同步（复用现有镜像机制，保留镜像目标自己的 listen 端口）。
  • 自动留档：提交成功后自动生成一条版本记录（本次推送的结果版本，与上一版本可对比回溯）；推送记录保留原始文本作为覆盖前保底。

结果与状态：预览 → 待确认（返回端口动作清单）；提交 → 成功，目标配置更新完成，推送任务记录逐端口动作（替换/新建/无变化）。

确认与撤销：提交是破坏性动作，但被「自动留档版本 + 推送记录保留原始文本」双重保底；任一端口提交失败则整体回滚（不落库），任务失败。

FR-5 查看推送结果 P0

用户与触发：命令执行后，用户回到系统查看预览或提交结果。

处理规则

  • 块管理页提供「推送记录」入口：按时间倒序列出推送任务（id、目标配置、端口数、状态：预览中/待确认/提交中/成功/失败、耗时）。
  • 预览报告：每个端口的动作判定（替换/新建/无变化）+ 失败行号清单（若有），并提供「确认提交」入口——用户在 Web 端也可直接确认，等价于执行提交命令。
  • 任务详情展示：原始文件文本（可折叠）、逐端口动作（替换/新建/无变化/保留）、失败清单（行号+原因，若有）。
  • 成功任务可「跳转到配置」直接进入块管理查看/编辑；失败任务展示报错清单并提示「修正后重新预览」。

结果：用户能确认推送「将要做什么 / 做了什么」，并能从记录直达配置。

FR-6 再次修改推送配置 P0

推送入库后的配置与手工编辑的配置完全同源：进入现有块管理页，可增删改监听点、子块与指令行。不新增第二套编辑逻辑（复用现有能力）。重复推送即执行 FR-4 差异对比与提交，修改不会被静默丢弃：修改过的端口再次推送会被替换（预期内，版本可回溯）。

自动留档（修改即自动留档）：系统内任何配置内容变更落库成功后，自动生成一条版本记录——无需手动点「保存」。连续高频编辑（如逐条调整指令值）采用短窗口合并 [Assumption, TBD]（默认 5 秒内连续变更合并为一条版本），避免碎片版本堆积；每条版本仍可在版本对比中查看变更。

5. 共享规则

规则定义
对比键配置文件内以 listen 端口唯一标识监听点（文件内自动识别）；端口缺失或重复均视为解析错误（全拒）。一个 server 多端口时取第一个 listen 为主键，其余端口跟随。
两阶段副作用边界预览阶段只读（解析+对比），不写库；仅提交阶段写入。预览结果在提交时校验仍有效，否则拒绝并提示重新预览。
差异动作分类同端口内容不同=替换；仅文件有=新建；同端口内容一致=无变化（跳过）；仅系统有=保留不删（永不提交删除）。
全拒 vs 部分成功解析存在错误 → 整次拒绝、不落库、返回行号清单；正确才进入差异与提交。
自动留档所有变更来源（推送提交成功、系统内修改落库）自动生成版本记录；高频连续编辑采用短窗口合并（默认 5 秒内合并为一条）[Assumption, TBD]。
覆盖保底提交即触发自动留档版本（结果版本），与推送记录保留的原始文本共同构成双重保底，可任选版本对比回溯。
镜像联动被提交替换的监听点为镜像源时，提交后自动同步镜像目标（保留目标自身 listen）。
凭证与记录推送凭证可独立生成/吊销；推送任务与凭证、目标配置、时间戳绑定记录。

6. 开放问题与假设

项类型内容
推送凭证[TBD]生成入口、有效期、吊销方式，以及是否限制为只读推送专用权限。
CLI 工具交付[Assumption, TBD]采用 Python 脚本分发（复用现有后端环境）打包发布；curl 为默认形态。
文件大小上限[TBD]单文件推送上限（建议默认 2 MB）。
解析边界[Assumption]upstream/map/变量插值等语法在无法映射时进入失败清单而非静默丢弃。
推送来源限制[Assumption]仅限系统可达的本地文件（curl -F 或 CLI 直读路径）；不做远程服务器 SSH 拉取。
预览有效期[Assumption]待确认预览默认 24 小时内有效，超时需重新预览。
多端口 server[Assumption]以第一个 listen 为主键，其余端口随该 server 整体替换/新建。
自动留档合并窗口[TBD]系统内修改自动留档的合并窗口时长（建议默认 5 秒），以及是否按「单次编辑会话」而非时间窗口合并。
评审入口：文档评审重点为 FR-2 凭证策略、FR-3 解析边界、FR-4 差异对比与提交语义三项；确认后进入技术设计。
